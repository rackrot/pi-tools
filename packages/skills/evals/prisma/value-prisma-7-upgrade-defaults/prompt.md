we just bumped `prisma` and `@prisma/client` from 6.x to 7.x in our node api (postgres, `@prisma/adapter-pg` created with only a `connectionString`, nothing else configured). before i update the team runbook, answer each of these for Prisma 7 as we now have it:

- Q1: after `prisma migrate dev` creates and applies a migration, does it also regenerate the client by itself?
- Q2: does `prisma migrate reset` run our seed script by itself?
- Q3: after `prisma db push`, is the client regenerated by itself?
- Q4: our drift check runs `prisma migrate diff --from-url "$PROD_URL" --to-schema-datamodel prisma/schema.prisma --exit-code`. does that command line still work unchanged?
- Q5: the staging database has a self-signed certificate and the v6 app connected to it with a plain `postgresql://` url and no ssl settings. will the v7 app connect to it with that same url and no other change?
- Q6: with the pool left at its defaults, is an idle database connection now closed sooner than it was under v6?

end your reply with exactly one line per question in the form `Q1: YES` or `Q1: NO`, Q1 to Q6 in order.
